# Installable Spa Log — 6.51.0 / Worker 3.8

Install from the existing secure Worker origin, using Chrome on Android → menu → Add to home screen → Install (or the in-app Install button when offered). The manifest provides a stable identity, standalone window, dark theme and 192/512px versions of the existing logo. Orientation is deliberately unrestricted for expanded landscape charts. Public Pages remains a development/reference address; in-app installation is offered only on the secure origin.

Open online once and wait for “Ready for offline startup on this device.” The versioned service worker precaches only the public interface, manifest, icons and logo. Existing local records/configuration supply offline history, models and entry saving. Private API, OAuth, weather, writes and all non-allowlisted requests bypass Cache Storage. Reconnecting retries normal authenticated sync; an expired session still requires sign-in. Cached forecast/weather context is not live weather. Offline data is device/browser-profile-specific, not a substitute for GitHub sync or backup; clearing site data removes it.

Updates install into a separate version cache and wait while any existing app window is open. The UI asks users to finish/save work, close **all** Spa Log windows and reopen. No forced reload, skipWaiting or clients.claim; unfinished inputs are not interrupted. Activation removes only old `j365-public-shell-*` caches, never localStorage or other cache namespaces. A failed/mismatched public-shell fetch aborts installation. Browser storage eviction can remove offline assets; reopening online restores them. The initial online setup is required.

Deployment: Worker 3.8 adds four fixed public asset routes and only `manifest-src 'self'; worker-src 'self'` to the interface CSP. Existing OAuth/CSRF/legacy/private API code is unchanged. `src/pwa-assets.js` is canonical; `node scripts/build-cloudflare-pwa.cjs` generates the standalone dashboard file from retained Worker 3.7. Keep previous Cloudflare deployment for rollback. Publish Pages assets, deploy Worker, verify paths/headers and install on the secure origin. Never publish secrets or private configuration to Pages.

For every future app release, bump package and APP_VERSION together, run `node scripts/build-pwa.cjs`, then `npm test`. The regression checks reject a stale generated service-worker version. Logo icon resizing is reproducible using `swift -module-cache-path /tmp/j365-swift-module-cache scripts/build-icons.swift` on macOS. `scripts/check-pwa-browser.cjs` is an optional real Chromium check using Playwright via `J365_PLAYWRIGHT` when not locally installed; it uses an isolated test origin/profile and no private data.

No chemistry equations, actual doses, historical records, schemas or cloud data are migrated. Notifications, background scheduled jobs and native-device integrations are intentionally outside this release.

Live rollout verification caught upstream negative-cache propagation after the first pre-publication probes. The fixed public routes add a server-generated freshness query (never caller parameters), matching the existing interface proxy strategy, so missing-file cache entries cannot block installation or delay service-worker updates.
